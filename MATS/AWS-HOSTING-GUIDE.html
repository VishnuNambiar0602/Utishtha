🎯 What You're Building

MATS (Medical Ambulance Tracking System) is a web application with 3 main parts:

🌐 Part 1: Frontend Website (MATS)

This is what users see and interact with:

  • Admin dashboard to manage ambulances
  • Driver interface to accept trips
  • Real-time GPS tracking on maps
  • Emergency call intake system
  • Medical report generation

Technology: React + TypeScript (just HTML, CSS, JavaScript files)

Where it goes: AWS S3 + CloudFront (like a super-fast file storage)

🤖 Part 2: GRASP2026 Backend (Medical AI)

This is the smart medical diagnosis system:

  • Analyzes patient symptoms
  • Suggests possible diseases
  • Provides AI explanations (XAI)
  • Generates medical reports

Technology: Python Flask API

Where it goes: AWS EC2 (a virtual computer in the cloud)

💾 Part 3: Supabase (Database & Storage)

This stores all your data:

  • Ambulance information
  • Trip/incident records
  • GPS tracking history
  • Medical report PDFs
  • Real-time updates

Technology: PostgreSQL database + File storage

Where it goes: Supabase Cloud (managed service, no AWS needed)

💡 Simple Analogy:

Think of it like a restaurant:

  • Frontend (S3/CloudFront) = The dining area where customers sit
  • Backend (EC2) = The kitchen where food is prepared
  • Database (Supabase) = The pantry where ingredients are stored

🏗️ How Everything Works Together

The Flow of Data:

  1. User opens website → CloudFront serves the React app from S3
  2. User creates emergency trip → Frontend saves to Supabase database
  3. User generates medical report → Frontend calls GRASP2026 API on EC2
  4. GRASP2026 analyzes symptoms → Returns diagnosis to frontend
  5. Frontend generates PDF → Saves to Supabase storage
  6. Real-time updates → Supabase pushes changes to all connected users

💾 Setting Up Supabase (Database)

1 Create Supabase Project
  1. Go to supabase.com
  2. Click "Start your project" → Sign up with GitHub
  3. Click "New Project"
  4. Fill in:
    • Name: mats-production
    • Database Password: Create a strong password (save it!)
    • Region: Choose closest to your users
    • Pricing Plan: Free (for now)
  5. Click "Create new project" (takes 2-3 minutes)
2 Get Your API Keys
  1. In Supabase dashboard, click "Settings" (gear icon)
  2. Click "API" in the left sidebar
  3. Copy these values (you'll need them later):
    Project URL: https://xxxxx.supabase.co anon public key: eyJhbGc...
  4. Save these in a safe place (like a password manager)
3 Create Database Tables
  1. In Supabase dashboard, click "SQL Editor" in the left sidebar
  2. Click "New query"
  3. Copy the entire content from MATS/supabase/schema.sql
  4. Paste it into the SQL editor
  5. Click "Run" (bottom right)
  6. You should see "Success. No rows returned"
✅ What This Does: Creates 4 tables:
  • ambulances - Stores ambulance fleet data
  • trips - Stores emergency incidents
  • gps_locations - Stores GPS tracking history
  • medical_reports - Stores medical report metadata
4 Create Storage Bucket for PDFs
  1. Click "Storage" in the left sidebar
  2. Click "Create a new bucket"
  3. Fill in:
    • Name: medical-reports
    • Public bucket: ✅ Check this (so PDFs can be downloaded)
  4. Click "Create bucket"
🎉 Supabase Setup Complete!

Your database is ready. Keep your API keys safe - you'll need them in the next steps.

🤖 Deploying GRASP2026 Backend (Medical AI)

📝 What We're Doing:

We're putting the Python medical diagnosis API on an AWS EC2 server (a virtual computer in the cloud).

1 Create EC2 Instance
  1. Log into AWS Console: console.aws.amazon.com
  2. Search for "EC2" in the top search bar
  3. Click "Launch Instance" (big orange button)
  4. Fill in:
    • Name: grasp2026-backend
    • Application and OS Images: Ubuntu Server 22.04 LTS (Free tier eligible)
    • Instance type: t2.medium (2 vCPU, 4GB RAM - needed for AI model)
    • Key pair: Click "Create new key pair"
      • Name: grasp2026-key
      • Type: RSA
      • Format: .pem (for Mac/Linux) or .ppk (for Windows)
      • Click "Create key pair" - it will download
      • SAVE THIS FILE! You can't download it again
    • Network settings: Click "Edit"
      • Auto-assign public IP: Enable
      • Firewall (security groups): Create new
        • Rule 1: SSH (port 22) - Source: My IP
        • Rule 2: Custom TCP (port 5000) - Source: Anywhere (0.0.0.0/0)
        • Rule 3: HTTPS (port 443) - Source: Anywhere (0.0.0.0/0)
    • Storage: 20 GB gp3 (default is fine)
  5. Click "Launch instance"
  6. Wait 2-3 minutes for it to start
  7. Click on the instance ID to see details
  8. Copy the Public IPv4 address (e.g., 54.123.45.67) - save this!
💰 Cost Alert: t2.medium costs about $0.0464/hour (~$34/month).
Free tier only covers t2.micro. Consider starting with t2.micro for testing, then upgrade if needed.
2 Connect to Your EC2 Instance

For Mac/Linux:

# Make key file secure chmod 400 grasp2026-key.pem # Connect to server (replace with your IP) ssh -i grasp2026-key.pem ubuntu@54.123.45.67

For Windows (using PuTTY):

  1. Download PuTTY: putty.org
  2. Open PuTTY
  3. Host Name: ubuntu@54.123.45.67 (your IP)
  4. Connection → SSH → Auth → Browse → Select your .ppk file
  5. Click "Open"
3 Install Required Software on EC2

Once connected to your EC2 instance, run these commands one by one:

# Update system sudo apt update && sudo apt upgrade -y # Install Python 3.10 and pip sudo apt install python3.10 python3-pip python3-venv -y # Install Git sudo apt install git -y # Install Nginx (web server) sudo apt install nginx -y # Install system dependencies for PyTorch sudo apt install python3-dev build-essential -y
4 Upload GRASP2026 Code to EC2

Option A: Using Git (Recommended)

# Clone your repository (if you have it on GitHub) git clone https://github.com/yourusername/GRASP2026.git cd GRASP2026/Medical-XAI/backend

Option B: Using SCP (Secure Copy)

On your local computer (not EC2), run:

# Navigate to your GRASP2026 folder cd /path/to/GRASP2026 # Copy files to EC2 (replace with your IP) scp -i grasp2026-key.pem -r Medical-XAI/backend ubuntu@54.123.45.67:~/

Then on EC2:

cd ~/backend
5 Install Python Dependencies
# Create virtual environment python3 -m venv venv # Activate virtual environment source venv/bin/activate # Install dependencies pip install --upgrade pip pip install -r requirements.txt # This will take 5-10 minutes (PyTorch is large)
☕ Take a break! Installing PyTorch and transformers takes time. Grab a coffee!
6 Test the API Locally
# Start the Flask app python app.py

You should see:

* Running on http://0.0.0.0:5000 Medical XAI model initialized successfully

Test it from your computer:

curl http://54.123.45.67:5000/health

Should return:

{"status":"healthy","model_loaded":true}

Press Ctrl+C to stop the server.

7 Set Up Gunicorn (Production Server)
# Install Gunicorn pip install gunicorn # Test Gunicorn gunicorn --bind 0.0.0.0:5000 --workers 2 --timeout 120 app:app

If it works, press Ctrl+C and continue.

8 Create Systemd Service (Auto-Start on Boot)
# Create service file sudo nano /etc/systemd/system/grasp2026.service

Paste this content (replace /home/ubuntu/backend if your path is different):

[Unit] Description=GRASP2026 Medical Diagnosis API After=network.target [Service] User=ubuntu WorkingDirectory=/home/ubuntu/backend Environment="PATH=/home/ubuntu/backend/venv/bin" ExecStart=/home/ubuntu/backend/venv/bin/gunicorn --bind 0.0.0.0:5000 --workers 2 --timeout 120 app:app Restart=always [Install] WantedBy=multi-user.target

Save and exit: Ctrl+X, then Y, then Enter

# Enable and start service sudo systemctl daemon-reload sudo systemctl enable grasp2026 sudo systemctl start grasp2026 # Check status sudo systemctl status grasp2026

You should see "active (running)" in green.

9 Configure Nginx (Reverse Proxy)
# Create Nginx config sudo nano /etc/nginx/sites-available/grasp2026

Paste this content:

server { listen 80; server_name 54.123.45.67; # Replace with your EC2 IP location / { proxy_pass http://127.0.0.1:5000; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_connect_timeout 120s; proxy_send_timeout 120s; proxy_read_timeout 120s; } }

Save and exit, then:

# Enable site sudo ln -s /etc/nginx/sites-available/grasp2026 /etc/nginx/sites-enabled/ # Test config sudo nginx -t # Restart Nginx sudo systemctl restart nginx
🎉 GRASP2026 Backend is Live!

Test it from your browser: http://54.123.45.67/health

Save this URL - you'll need it for the frontend: http://54.123.45.67

📝 Useful Commands:
# View logs sudo journalctl -u grasp2026 -f # Restart service sudo systemctl restart grasp2026 # Stop service sudo systemctl stop grasp2026 # Check if service is running sudo systemctl status grasp2026

🌐 Deploying MATS Frontend (Website)

📝 What We're Doing:

We're building the React app into static files and uploading them to AWS S3, then serving them through CloudFront CDN.

1 Configure Environment Variables

On your local computer, navigate to the MATS folder and create/edit .env file:

cd MATS nano .env

Add these values (replace with your actual keys):

# Google Gemini API Key VITE_API_KEY=your_gemini_api_key_here GEMINI_API_KEY=your_gemini_api_key_here # Supabase Configuration VITE_SUPABASE_URL=https://xxxxx.supabase.co VITE_SUPABASE_ANON_KEY=your_supabase_anon_key_here # GRASP2026 Backend URL (your EC2 IP) VITE_GRASP2026_API_URL=http://54.123.45.67
⚠️ Important:
  • All variables must start with VITE_ to be included in the build
  • Never commit this file to Git (it's in .gitignore)
  • These values will be embedded in your JavaScript (visible to users)
2 Build the React App
# Install dependencies (if not already done) npm install # Build for production npm run build

This creates a dist/ folder with all your website files.

✅ Build Complete! You should see:
  • dist/index.html
  • dist/assets/ (JS and CSS files)
3 Create S3 Bucket
  1. Go to AWS Console → Search for "S3"
  2. Click "Create bucket"
  3. Fill in:
    • Bucket name: mats-frontend-prod (must be globally unique)
    • Region: Choose closest to your users (e.g., us-east-1)
    • Block Public Access: ❌ UNCHECK "Block all public access"
    • Check the warning acknowledgment box
  4. Leave everything else as default
  5. Click "Create bucket"
4 Enable Static Website Hosting
  1. Click on your bucket name
  2. Go to "Properties" tab
  3. Scroll down to "Static website hosting"
  4. Click "Edit"
  5. Select "Enable"
  6. Fill in:
    • Index document: index.html
    • Error document: index.html (for React Router)
  7. Click "Save changes"
  8. Copy the "Bucket website endpoint" URL (e.g., http://mats-frontend-prod.s3-website-us-east-1.amazonaws.com)
5 Set Bucket Policy (Make Files Public)
  1. Go to "Permissions" tab
  2. Scroll to "Bucket policy"
  3. Click "Edit"
  4. Paste this policy (replace mats-frontend-prod with your bucket name):
{ "Version": "2012-10-17", "Statement": [ { "Sid": "PublicReadGetObject", "Effect": "Allow", "Principal": "*", "Action": "s3:GetObject", "Resource": "arn:aws:s3:::mats-frontend-prod/*" } ] }
  1. Click "Save changes"
6 Upload Files to S3

Option A: Using AWS Console (Easy)

  1. Go to "Objects" tab
  2. Click "Upload"
  3. Click "Add files" and "Add folder"
  4. Select ALL files from your dist/ folder
  5. Click "Upload"
  6. Wait for upload to complete

Option B: Using AWS CLI (Faster for updates)

# Configure AWS CLI (first time only) aws configure # Enter your AWS Access Key ID # Enter your AWS Secret Access Key # Enter region (e.g., us-east-1) # Enter output format: json # Upload files cd MATS aws s3 sync dist/ s3://mats-frontend-prod/ --delete
💡 Pro Tip: Use aws s3 sync for future updates. It only uploads changed files!
7 Test Your Website

Open the S3 website endpoint URL in your browser:

http://mats-frontend-prod.s3-website-us-east-1.amazonaws.com

You should see your MATS application!

⚠️ Note: This URL is not HTTPS and not user-friendly. We'll fix this with CloudFront next!
8 Create CloudFront Distribution (CDN)
  1. Go to AWS Console → Search for "CloudFront"
  2. Click "Create distribution"
  3. Fill in:
    • Origin domain: Select your S3 bucket from dropdown
    • Origin access: Public
    • Viewer protocol policy: Redirect HTTP to HTTPS
    • Allowed HTTP methods: GET, HEAD, OPTIONS, PUT, POST, PATCH, DELETE
    • Cache policy: CachingOptimized
    • Price class: Use all edge locations (best performance)
    • Alternate domain name (CNAME): Leave empty for now (we'll add later)
    • Default root object: index.html
  4. Click "Create distribution"
  5. Wait 5-10 minutes for deployment (status will change from "Deploying" to "Enabled")
  6. Copy the "Distribution domain name" (e.g., d1234abcd.cloudfront.net)
9 Configure Error Pages (for React Router)
  1. Click on your distribution ID
  2. Go to "Error pages" tab
  3. Click "Create custom error response"
  4. Fill in:
    • HTTP error code: 403: Forbidden
    • Customize error response: Yes
    • Response page path: /index.html
    • HTTP response code: 200: OK
  5. Click "Create custom error response"
  6. Repeat for error code 404: Not Found
🎉 Your Website is Live!

Visit: https://d1234abcd.cloudfront.net

✅ HTTPS enabled

✅ Global CDN (fast worldwide)

✅ React Router working

🔄 How to Update Your Website:
# 1. Make changes to your code # 2. Rebuild npm run build # 3. Upload to S3 aws s3 sync dist/ s3://mats-frontend-prod/ --delete # 4. Invalidate CloudFront cache (replace with your distribution ID) aws cloudfront create-invalidation --distribution-id E1234ABCD --paths "/*"

🌍 Setting Up Your Domain Name (Optional)

📝 What We're Doing:

Instead of d1234abcd.cloudfront.net, you can use your own domain like mats.yourdomain.com

1 Buy a Domain (if you don't have one)

You can buy from:

  • AWS Route 53: $12/year for .com
  • Namecheap: ~$10/year
  • GoDaddy: ~$15/year
  • Google Domains: $12/year
2 Request SSL Certificate (Free!)
  1. Go to AWS Console → Search for "Certificate Manager"
  2. IMPORTANT: Switch region to us-east-1 (N. Virginia) - CloudFront only works with certificates in this region!
  3. Click "Request certificate"
  4. Select "Request a public certificate"
  5. Fill in:
    • Domain names:
      • mats.yourdomain.com
      • *.yourdomain.com (wildcard, optional)
    • Validation method: DNS validation
  6. Click "Request"
  7. Click on the certificate ID
  8. You'll see CNAME records to add to your DNS
  9. Add these CNAME records to your domain's DNS settings
  10. Wait 5-30 minutes for validation (status will change to "Issued")
3 Add Domain to CloudFront
  1. Go back to CloudFront
  2. Click on your distribution
  3. Click "Edit"
  4. Fill in:
    • Alternate domain names (CNAMEs): mats.yourdomain.com
    • Custom SSL certificate: Select your certificate from dropdown
  5. Click "Save changes"
4 Point Domain to CloudFront

In your domain's DNS settings, add:

Type Name Value
CNAME mats d1234abcd.cloudfront.net

Wait 5-60 minutes for DNS propagation.

🎉 Your Custom Domain is Live!

Visit: https://mats.yourdomain.com

🔧 Common Problems & Solutions

Problem: Website shows "Access Denied"

Solution:

  • Check S3 bucket policy is set correctly
  • Verify "Block Public Access" is OFF
  • Make sure all files are uploaded to S3

Problem: Medical reports not generating

Solution:

  • Check GRASP2026 backend is running: sudo systemctl status grasp2026
  • Verify VITE_GRASP2026_API_URL in .env is correct
  • Check EC2 security group allows port 5000
  • Test API directly: curl http://your-ec2-ip/health

Problem: Real-time updates not working

Solution:

  • Check Supabase URL and keys in .env
  • Verify Supabase project is active
  • Check browser console for errors (F12)
  • Rebuild and redeploy: npm run build && aws s3 sync dist/ s3://your-bucket/

Problem: EC2 instance not responding

Solution:

  • Check instance is running in EC2 console
  • Verify security group allows your IP for SSH
  • Try rebooting: EC2 Console → Actions → Instance State → Reboot
  • Check system logs: EC2 Console → Actions → Monitor and troubleshoot → Get system log

Problem: CloudFront showing old content

Solution:

# Invalidate CloudFront cache aws cloudfront create-invalidation \ --distribution-id YOUR_DISTRIBUTION_ID \ --paths "/*"

Problem: "Out of memory" errors on EC2

Solution:

  • Upgrade to larger instance (t2.medium → t2.large)
  • Add swap space:
    sudo fallocate -l 2G /swapfile sudo chmod 600 /swapfile sudo mkswap /swapfile sudo swapon /swapfile
  • Reduce Gunicorn workers in systemd service file

Problem: SSL certificate not validating

Solution:

  • Make sure you added CNAME records to your domain's DNS
  • Wait 30 minutes for DNS propagation
  • Check DNS records: nslookup your-domain.com
  • Certificate MUST be in us-east-1 region for CloudFront
